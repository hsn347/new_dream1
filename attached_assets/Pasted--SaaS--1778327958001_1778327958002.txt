أريد الآن تحويل **صفحة المستخدم** من مجرد صفحات تجريبية إلى **نظام فعلي متكامل داخل SaaS**، بحيث تصبح كل الصفحات التالية مرتبطة بقاعدة البيانات والوكيل الحقيقي:

* صفحة المنتجات
* صفحة الكوبونات
* صفحة بيانات العمل التجاري
* صفحة المحادثات
* أي صفحة مرتبطة ببيانات العميل داخل لوحة المستخدم

**مهم جدًا:**
هذه الصفحات موجودة حاليًا بشكل UI فقط، وأريد منك الآن **دمجها فعليًا** مع النظام والوكيل، مع الحفاظ على نفس التصميم الجميل الحالي.

---

# 1) الهدف العام

أريد أن تصبح صفحة المستخدم جزءًا حقيقيًا من نظام الوكيل، بحيث:

* أي منتج يضيفه المستخدم يدخل فعليًا في قاعدة البيانات
* أي كوبون يضيفه المستخدم يصبح فعليًا متاحًا للوكيل
* أي تعديل على بيانات العمل التجاري يتم حفظه فعليًا
* المحادثات تصبح محفوظة ومتصلة بالوكيل الحقيقي
* بيانات المتجر تُستخدم فعليًا في ردود الوكيل
* كل شيء يكون **multi-tenant**، أي كل مستخدم يرى بياناته فقط

---

# 2) صفحة المنتجات — تحويلها إلى نظام فعلي

أريد صفحة المنتجات أن تعمل فعليًا، وليس مجرد واجهة.

## المطلوب:

* إضافة منتج جديد فعليًا في قاعدة البيانات
* تعديل منتج
* حذف منتج
* عرض المنتجات الخاصة بالمستخدم الحالي فقط
* حفظ صورة المنتج
* حفظ:

  * اسم المنتج
  * الوصف
  * الكمية
  * وحدة المنتج
  * السعر
  * سعر المساومة الاختياري
  * العملة
  * صورة المنتج
  * حالة المنتج: متوفر / غير متوفر

## مهم جدًا:

عند إضافة أو تعديل منتج:

* يجب أن يتم تحديث معرفة الوكيل مباشرة
* وإذا كان النظام يستخدم vector embeddings، يجب إعادة فهرسة المنتج أو تحديث embeddings الخاصة به
* حتى يستطيع الوكيل الرد على أسئلة المنتج بشكل فعلي

---

# 3) صفحة الكوبونات — تحويلها إلى نظام فعلي

أريد صفحة الكوبونات أن تكون مرتبطة بالقاعدة فعليًا.

## المطلوب:

* إضافة كوبون جديد
* تعديل كوبون
* حذف كوبون
* عرض الكوبونات الخاصة بالمستخدم الحالي فقط
* حفظ:

  * رمز الكوبون
  * تاريخ البداية
  * تاريخ النهاية
  * نوع الخصم: نسبة أو مبلغ ثابت
  * قيمة الخصم
  * المنتجات التي يشملها الكوبون
  * حالة الكوبون: فعال / منتهي / معطل

## مهم جدًا:

* الوكيل يجب أن يستخدم بيانات الكوبونات فعليًا عند الرد
* إذا سأل العميل عن خصم، يجب أن يقدر يجيب من البيانات الحقيقية
* إذا كان الكوبون غير صالح، يجب ألا يظهر كأنه صالح

---

# 4) صفحة بيانات العمل التجاري — تحويلها إلى نظام فعلي

أريد صفحة بيانات العمل التجاري أن تحفظ وتسترجع بيانات حقيقية.

## المطلوب:

* حفظ بيانات النشاط التجاري فعليًا
* تعديل البيانات
* عرضها للمستخدم الحالي فقط

## البيانات المطلوبة:

* اسم العمل التجاري
* وصف العمل التجاري
* أرقام التواصل البشري
* مواقع الفروع
* روابط السوشيال ميديا بصيغة key/value
* رابط المتجر الإلكتروني
* ساعات العمل
* الحسابات البنكية
* سياسة الاسترجاع
* أي بيانات إضافية يحددها المستخدم

## مهم جدًا:

هذه البيانات يجب أن تدخل فعليًا في معرفة الوكيل حتى يرد منها مباشرة.

---

# 5) صفحة المحادثات — تحويلها إلى نظام فعلي

أريد صفحة المحادثات أن تصبح متصلة فعليًا بالمحادثات الحقيقية القادمة من واتساب.

## المطلوب:

* عرض المحادثات الفعلية الخاصة بالمستخدم
* حفظ الرسائل في قاعدة البيانات
* عرض كل محادثة مع رسائلها
* عرض حالة العميل
* عرض حالة الوكيل مع العميل
* إمكانية إيقاف الوكيل على محادثة معينة
* إمكانية تفعيل الوكيل مرة أخرى
* البحث داخل المحادثات
* الفلترة حسب:

  * آخر تفاعل
  * العميل
  * حالة الوكيل
  * الاهتمام
* عرض ملخص ذكي لكل عميل إن وجد

## مهم جدًا:

* هذه ليست بيانات mock
* هذه محادثات حقيقية مرتبطة بالواتساب والـ webhook
* عند وصول رسالة جديدة، يجب أن تظهر فعليًا في الصفحة

---

# 6) ربط هذه الصفحات بالوكيل فعليًا

أريد أن تكون هذه الصفحات ليست منفصلة عن الوكيل، بل جزءًا من نفس المنظومة.

## المطلوب:

عند إضافة أو تعديل:

* منتج
* كوبون
* بيانات عمل تجاري
* سياسة عامة
* إعداد شحن

يجب أن يحدث التالي:

1. حفظ البيانات في قاعدة البيانات
2. تحديث ذاكرة/معرفة الوكيل
3. إعادة بناء أو تحديث الـ vector index عند الحاجة
4. جعل الردود القادمة من الوكيل تعتمد على آخر البيانات

---

# 7) قاعدة البيانات

أريد استخدام قاعدة بيانات حقيقية تدعم SaaS multi-tenant.

## الجداول المقترحة:

* users
* businesses
* products
* coupons
* conversations
* messages
* customer_profiles
* general_knowledge
* shipping_rules
* agent_settings
* whatsapp_connections
* model_connections
* product_embeddings
* coupon_embeddings
* knowledge_embeddings

## مهم جدًا:

كل جدول يجب أن يكون مرتبطًا بـ:

* user_id
* أو tenant_id
  حتى لا يختلط بيانات العملاء بين المستخدمين

---

# 8) الدمج مع الواجهة الحالية

لا أريد إعادة بناء الصفحات من الصفر.

أريد:

* الحفاظ على نفس التصميم الحالي
* فقط تحويل الصفحات من UI تجريبي إلى functional pages
* إضافة CRUD حقيقي
* إضافة API routes حقيقية
* ربطها بقاعدة البيانات
* ربطها بالوكيل

---

# 9) المتطلبات التقنية

أريد تنفيذ هذا بطريقة منظمة:

## Backend

* Services layer
* Database layer
* API routes layer
* Validation layer
* Provider abstraction إن لزم

## Frontend

* Forms حقيقية
* Save / Update / Delete
* Loading states
* Success / Error alerts
* Refresh للبيانات بعد الحفظ
* توافق ممتاز مع الجوال

---

# 10) سلوك النظام بعد التحويل

بعد هذا التعديل أريد أن يكون النظام كالتالي:

* المستخدم يدخل المنتجات والكوبونات وبيانات النشاط
* البيانات تحفظ فعليًا
* الوكيل يقرأها عند الرد
* المحادثات تحفظ فعليًا
* أي تعديل يظهر مباشرة
* النظام يظل SaaS متعدد المستخدمين
* كل مستخدم يملك بياناته الخاصة فقط

---

# 11) المطلوب النهائي منك

أريدك الآن أن:

* تربط صفحة المستخدم بقاعدة البيانات
* تجعل المنتجات والكوبونات وبيانات العمل والمحادثات تعمل فعليًا
* تدمج كل ذلك مع الوكيل الحقيقي
* وتحوّل الصفحات الحالية من تجريبية إلى **Production-ready MVP**

ابدأ بالأولوية التالية:

1. المنتجات
2. بيانات العمل التجاري
3. الكوبونات
4. المحادثات
5. ربط البيانات بالوكيل والـ embeddings
